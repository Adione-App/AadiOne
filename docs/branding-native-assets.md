# Branding: app icons need a new app release

Admin Panel → Settings → **Branding & Identity** manages every Aadione brand asset. Most of them update live. The **app icons** do not: they are part of the installed Android / iOS app, and no server can change an icon on a phone.

| Asset (Branding & Identity) | Where it shows | How it changes |
| --- | --- | --- |
| Main brand logo | Fallback for every logo; seller statement and financial PDFs | **Live** — panels and website within ~1 minute of publishing; next PDF generated |
| Logo for light backgrounds | Admin Panel sidebar and sign-in, website header, customer app sign-in screen | **Live** (customer app: from its next refresh) |
| Logo for dark backgrounds | Website footer | **Live** |
| Website favicon | Browser tab of the panels and the website; home-screen shortcut of the websites | **Live** (the built-in favicon in each `index.html` shows for the first moment of a fresh visit) |
| Customer app logo | Customer app: Home footer, About, update screen | **Live**, from the app's next refresh |
| Customer app start-up logo | Customer app start-up screen (the in-app loading screen) | **Live**, from the launch after the app has downloaded it |
| Seller Panel logo | Seller Panel sidebar, sign-in, registration and onboarding | **Live** |
| Android launcher icon (foreground / background) | The Android app icon on the home screen | **Next Android release only** |
| iOS app icon | The iPhone app icon | **Next iOS release only** |

The customer app's **native splash** is intentionally a blank 1×1 image (`mobile/app.json` → `expo-splash-screen`). The logo customers see at launch is the in-app start-up screen, which is the live "start-up logo" above. There is no separate seller mobile app: sellers use the Seller Panel (web).

## What publishing an app icon does — and does not do

- It **stores** the checked PNG (1024 × 1024; iOS: no transparency; Android foreground: transparent) as the **source for the next native build**, with its history.
- It does **not** change any installed app, trigger a build or submit anything to Google Play / the App Store.
- Phones keep the current icon until a new release containing the new icon is approved, built, published in the store and installed.

## Making a release with a new icon (only after the owner approves the release)

1. In Branding & Identity, open the icon and use **Download published PNG** (or take `pngUrl` from `GET /api/v1/admin/branding`).
2. Replace the source files in `mobile/assets/` (keep the names, so `mobile/app.json` needs no change):
   - Android foreground → `adaptive-icon-foreground.png` (1024 × 1024, transparent, artwork inside the central 66%)
   - Android background → `adaptive-icon-background.png` (1024 × 1024, opaque)
   - iOS → `icon-ios.png` (1024 × 1024, opaque)
3. **Android:** the committed native project (`mobile/android`) is built as-is by EAS — `app.json` icon fields are NOT applied automatically. Regenerate the launcher images in `mobile/android/app/src/main/res/mipmap-*/` (`ic_launcher.webp`, `ic_launcher_round.webp`, `ic_launcher_foreground.webp`, `ic_launcher_background.webp`): for example with Android Studio → *New → Image Asset* (Launcher Icons, Adaptive and Legacy) from the two PNGs. Review the diff: only these icon files should change.
4. **iOS:** the iOS project is generated by EAS from `app.json` (`expo.icon`), so replacing `icon-ios.png` is enough.
5. Bump the version (`mobile/app.json` `version`, Android `versionCode` in `app.json` **and** `mobile/android/app/build.gradle`, iOS `buildNumber`).
6. Build and test on a real phone (`eas build --profile preview`), then the store build (`eas build --profile production`) and store submission — each only with the owner's approval.

Store listings (the icon shown on Google Play / the App Store page, 512 × 512 for Play) are uploaded separately in the Play Console / App Store Connect.
